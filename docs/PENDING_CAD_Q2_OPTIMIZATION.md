# CAD Q2 流程修正與驗證

## 範圍

依2026-10-18 Q2實測修正目前圖面流程，使用本機Strata `qwen3.8-flash-next-q2_0`、128K、reasoning_effort=none。只建立必要的隔離測試版，不進版、更新dist、製作安裝包或推送。公司原始250圖元DWG未提供；本機使用相同需求的645圖元法蘭板，不宣稱已修復公司未重現的首次revision拒絕。

## 程式與提示修改

- `cad_session`由程式保留首次成功讀取的版本／文件、最後原生修改結果及停止原因。`latest`刷新仍沿用原版本；不支援、結果未知或使用者取消後停止CAD操作，不因快照撤銷改讀另一套CAD。
- 快照保留最近實際交付的精確圖元資料（最多10筆／8KB），同一snapshot_id可直接沿用。新快照清空；不截斷單筆資料，不恢復跨任務的已讀Handle與寫入確認。
- 總覽增加由3–64條直線或可讀封閉直線折線構成的輪廓：邊數、外接框、框中心與尺寸。只描述連通與平面閉合，未檢查自交，不把框中心說成面積重心或命名零件。
- CAD基本流程與`handle/kind/value`常駐，圓半徑使用「目標直徑除以2」公式，移除固定Ø15範例，避免混入實際回報。無歧義且有精確資料就直接編輯；原生verification通過可finish，不為恢復舊快照再讀圖。
- 新模型不再看到舊全圖分頁入口，後端保留相容處理。停止後從本輪工具目錄移除CAD操作，執行邊界也拒絕重試。CAD進度筆記改為簡短新增進展，精確ID由程式提供。
- 第一輪實際2008成功後，模型仍以自行產生的snapshot_id查詢；執行邊界拒絕，之後正常交付。依此補上工具生命週期：沒有快照就不公告cad_query／cad_preview，沒有作用中文件授權就不公告cad_active_edit；仍可finish或先讀新快照，不以提示詞取代執行驗證。
- 第一份隔離GUI測試仍出現Q2把未載入技能誤認成無CAD能力／需額外授權。補強原生與文字協定的CAD目前圖面例外、`load_skill`啟動說明；用同一首輪輸入重播2008／2022均改為直接載入cad-active（約6.879／4.161秒），只算推論驗證，不算實際CAD工具執行。

## Undo相容方法

2008缺少COM StartUndoMark／EndUndoMark，且直接COM屬性寫入無法納入原生Undo。已驗證的方法是Application.RunCommand固定Begin／End、等待實際群組旗標，再以程式產生的有限原生LISP修改，取得帶nonce的完整回條。只支援圓半徑與ACI顏色；其他修改／新增／混合指令在寫入前拒絕。整批先驗證，原生端另查目前文件、單位、ModelSpace、類型、舊值與圖層鎖；不接受模型LISP／指令／路徑。

2022的COM Undo標記在原生批次讀取加入後，無法可靠跨過SendCommand讀回。改用已實測的原生Begin／End群組包住原有COM修改、Regen與全圖核對，等待群組旗標，不以COM返回當成完成。兩版本的群組都由ExitStack在整段核對後或例外時結束；失敗不自動Undo，也不儲存或關閉使用者圖面。

仍有範圍限制：2022修改完成後若另行刷新全圖快照，這個唯讀LISP命令可能留下空Undo項目，下一次Undo先移除該讀取紀錄。將額外讀取放入空群組仍未改善；沒有以自動Undo清除，避免撤銷使用者操作。正常完成流程以修改工具內的全圖核對為準，不需額外刷新。2008額外讀回後一次Undo實測仍完整還原。
