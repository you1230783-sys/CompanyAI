# Outlook 日期查詢與分類資料夾

2026-09-17：修正原先日期按鈕僅查預設收件匣，無法找到規則移轉至其他資料夾／PST 的郵件。

## 操作範圍

- 預設「所有已載入信箱與本機資料檔」：透過 Outlook Stores 列舉 Exchange 與已開啟的 PST，逐層查詢郵件資料夾。不掃描 C 槽、不直接讀寫 PST／OST、不自動載入其他資料檔。
- 「Outlook 目前資料夾及子資料夾」：先在 Outlook 郵件清單點選分類資料夾或某個資料檔的根目錄，再按日期按鈕。可用來縮小查詢，或明確查寄件備份等資料夾。
- 「預設收件匣及子資料夾」：查預設收件匣與其分類樹，不包含移到其他根目錄或 PST 的郵件。
- 「讀取目前選取」維持直接讀取選中的單封／多封，不受日期查詢範圍影響。

全部範圍以 Store 的預設資料夾 ID 排除寄件備份、草稿、寄件匣、刪除的郵件、垃圾郵件、同步問題及其子樹；另以 PR_FOLDER_TYPE 排除搜尋資料夾。自訂同名資料夾不按名称排除。行事曆／聯絡人等非郵件資料夾不讀取 Items，但繼續列舉其子資料夾。

PST 通常用於本機保存；OST 是 Exchange 等帳號的離線快取，不能只憑 C 槽有檔案判定是獨立歸檔。程式統一透過目前 Outlook 工作階段操作，能讀取的郵件仍取決於已載入的資料檔、同步狀態與權限。

## 數量、排序與資料邊界

三天內含今天及前兩天，本週從週一開始，到今天為止；依收件日期判斷，不依規則搬移時間。以 OLE DATE 數值比較本機日期，保留小數時間合併排序，不解析本機顯示的日期字串。

每個資料夾先依 ReceivedTime 遞減排序，未讀模式先套用 UnRead Restrict。遇到早於起日的信件即停止該資料夾；最多取得該資料夾前 50 個符合條件的候選，再跨資料夾合併取最新 50 封。較晚走訪的資料夾仍有機會取代較舊候選，不是先走訪先佔滿。

一次最多走訪 500 個資料夾、檢查 10,000 個項目，或執行 30 秒；時間與取消在 COM 呼叫間檢查，無法強制打斷 Outlook 正在等待的對話框。超出上限、超過 50 封或讀取失敗均顯示截斷／不完整。若走訪上限先到，清單只是已檢查部分的最新郵件，不能代表整個信箱的最新 50 封。

同一 StoreID＋EntryID 不重複列出；規則複製所產生的不同實體副本保留，不以主旨或日期猜測去重。結果顯示 Outlook 資料夾路徑，方便辨識副本。EntryID／StoreID 仍只留在 Rust；資料夾顯示路徑不是磁碟資料檔路徑，會隨勾選後的基本資訊交給 AI。

查詢不讀 Body、不匯出 MSG、不傳伺服器、不更改未讀狀態。分析與自動補充沿用原先確認流程。

## 驗證與公司實測

記憶體 IDispatch 回歸測試覆蓋空 Exchange 收件匣與 PST 分類樹、六個日期／未讀組合、排除系統與搜尋資料夾、未來／舊信、取消、部分讀取失敗、資料夾上限；純函式測試覆蓋跨資料夾最新 50 封與跨年月日期。WebView2 自檢驗證三種範圍與六種按鈕的命令組合、來源資料夾文字顯示。

上述測試不啟動真實 Outlook。公司仍須在 Outlook 2024 準備 Exchange、PST 分類子資料夾及已讀／未讀郵件，逐一核對清單、排序、來源、超量提示與未讀狀態不變；另驗證無權限／未同步／未開啟 PST、規則移動與複製、副本選取後 MSG 匯出。完整建置結果以 offline/verification.json 為準，不代表 Outlook 實機驗收通過。
