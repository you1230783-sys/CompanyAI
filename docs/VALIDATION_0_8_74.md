## 閱讀筆記能確認什麼

- 原生測試已確認：八段共用預算、截斷後區段核對、成功閱讀後必須保存筆記、已存區段重用、checkpoint還原與來源版本變更拒絕。固定參數測試不代表模型理解正確。
- 累積筆記與最近三頁目錄索引獨立於滑動工作筆記保存；壓縮不會刪除這些資料。目錄快照只證明列過檔名，不能當作讀過內容。
- 新任務啟用這份契約；舊版checkpoint預設不隱式切換協定，也不補造先前未保存的閱讀成果。本輪模型測試使用全新任務。
- 對已覆蓋原文，模型可在有具體缺漏理由時要求最多40行且2,000字元的精確補讀，保存後重複同一小窗改回筆記。避免摘要漏掉常數時完全無法核對，也避免整檔反覆重讀。
- `compact_context`仍要求工作筆記不超過2,000字元；現在錯誤明示實際字數，並提醒已有閱讀筆記時只寫100–300字交接，不複製整份函式清單。

這些機制能確認「資料可接回」；不能保證模型會選對入口、寫對摘要、停止反覆查筆記，或畫對箭頭。尚無同提示詞、同模型的受控舊版基準，不能宣稱節省特定比例的tokens或輪數。

### 真模型報告採用情境

R9以正式release EXE及已初始化Python環境，請GPT-6 Luna low分析合成CSV `[1,2,4,7]`，使用同一次計算結果產出Word／Excel與三值長條圖，並明確要求綁定欄位、不安裝套件。13輪後模型以finish結束，但沒有任何交付檔案，因此判定需求未完成，不能因原生回報`FINISHED_REQUIRES_REVIEW`就列為成功。

該次曾有成功Python結果（有效4筆、平均3.5、最小1、最大7），也有匯入未提供的`docx`及`matplotlib`失敗。模型未呼叫數值登記／套用工具，最後誤稱沒有Office工具；實際請求已提供`create_working_copy`、`register_report_values`、`apply_report_values`及`export_report_values`，Office指南首段也明示新建DOCX／XLSX方式。此結果顯示固定原生鏈路通過，仍不能保證低階模型會自動採用正確工具。

R11用相同提示詞與資料測Strata，確實登記四個計算值、匯出CSV、建立Word表格並呼叫apply_report_values，卻在真正空白儲存格反覆觸發原生「Office文字修改結果不一致」。已取消這個私人測試，保留原始參數、暫存副本與失敗紀錄；不是模型沒有使用工具，也不能拿原來「待填」案例的通過冒稱空白格通過。

新增原生案例已用修正前EXE重現：有「待填」文字的表格可通過，空白表格失敗。修正只讓裁切Word段落尾端標記後的End不小於原Start，保留逐區塊內容／來源／格式及保存重開核對。Word的End小於Start時會連帶移動Start，與這個空範圍問題一致，見[Microsoft Range.End說明](https://learn.microsoft.com/en-us/dotnet/api/microsoft.office.interop.word.range.end?view=word-pia)。修正後原生與模型復測結果另記；修正前0.8.74完整建置／NSIS證據不當作修正後結果。

R13使用修正後同一EXE、相同提示詞及新合成資料，62輪後因四次重複出圖／綁定而取消，完整模型報告需求判定未完成。已成功登記同一次Python的4、3.5、1、7；模型真的建立四個空白Word數值格並成功套用，沒有再出現原生「文字修改結果不一致」。最後一次原生工作副本讀回，Word與Excel的指標名稱及數值均獨立核對相符，CSV為最小1／平均3.5／最大7；第一張PNG已檢視，三根長條正確。

但Word／Excel只停留在工作副本，沒有save_copy或finish交付；輸出目錄只有CSV與四張PNG，不能列為完整報告成功。第31輪成功壓縮後，模型反覆把已匯出的PNG列為待辦，重做圖表與已完成綁定；原始stats.csv只讀一次，五次完全重複的文字讀回均為工作副本；未重新計算統計。14次原生工具／參數錯誤之外，亦曾有多工具呼叫補正。這是一般多成果進度仍會回退的證據，閱讀筆記不能代表所有類型任務都不重做。API實際輸入累積921,130、輸出33,019、總計954,149 tokens；未做受控舊版比較，不宣稱省用量。

此次模型把Excel空白欄建立為文字欄，套用後為含單位的文字（如「3.50 value」），原生讀回核對的是這些文字值，不冒稱數值儲存格。已有數值類型的模板欄保留數字，不附加單位；文字欄包含單位。固定原生鏈路已另行完成Word／Excel保存重開、共同圖表數值與錯值拒絕，不能代替R13缺少的模型交付。
