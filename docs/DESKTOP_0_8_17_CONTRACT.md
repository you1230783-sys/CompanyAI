# 0.8.17 專案歷程、重試與 UI

沿用 0.8.16 的 TXT／MD、原檔唯讀、副本輸出與 AppContainer 契約。本版合併先前暫存的專案 UI、VNC 更新對話框調整，只發布 EXE 與簽署 EXE 更新清單，不重建 NSIS 或歷史 ZIP。

## 通知與操作歷程

- 通知中心的標題／摘要各顯示最多 50 個可見字元，超過加省略號；不截斷底層資料或改變已讀／開啟通知行為。
- 右上角一般提示三秒後隱藏；專案工具進度另在對話內顯示摺疊卡片，不會隨提示消失。
- 卡片預設顯示最新步驟，例如閱讀檔案、建立副本、編輯文字、儲存副本。展開查看同次任務歷程，進度更新不收合使用者已展開的卡片。
- 歷程限制 120 筆、每筆 300 字；只保留操作名稱、成功／失敗與等待狀態，不放工具參數或文件全文。完成／失敗後寫入本機加密對話，切換對話與重新啟動後仍可查看。舊版任務沒有歷程時不憑空補造。

## 包裝工具 JSON 的有限重送

例如 `工具：{"action":"tool",...}`：若包裝文字裡只有一個完整且符合既有工具 schema 的物件，桌面不執行該物件，而是把原回覆與格式修正要求送回模型。修正要求明確表示原操作尚未執行，要求保留 operation_id、request，僅輸出 JSON。

只有純 JSON 通過既有驗證後才執行；操作 ID 去重仍生效。同次專案任務最多修正兩次，並計入既有 20 輪與 30 分鐘上限。多份 JSON、未知工具、不完整 JSON，以及文字包裝的 finish 結果，不擅自挑選、當作工具或反覆重試。格式修正發生在已取得伺服器完成回覆後，新一輪有新的 client_request_id；網路提交不明則仍查原 ID。

## 使用者按「重新再試一次」

- 按鈕位於目前對話最新一輪的訊息操作列，適用一般聊天及專案。送出對話 ID、提問位置、訊息數量與原 request_id；原生層核對，避免快速切換對話或連點後重試錯誤內容。
- 原回答、錯誤說明與既有成果保留。重試新增一次提問／回覆紀錄，實際送出的上下文回到首次提問，避免把同次失敗答案當成下一次指示；草稿保留。
- 一般聊天沿用原模型、模式、skills 與原附件。附件已到期／移除或原模型不可用時停止並提示，不悄悄漏掉附件或改模型。新版提問在本機保存重試設定，即使成功任務卡被清除仍可重試。舊版沒有設定且原任務已清除的純文字，使用目前模型；舊附件無法確定對應關係時要求重新加入。
- 提交結果不明時，使用原請求 ID 和內容重新確認；已知仍執行中或取消狀態未確認時不另建新請求。已停止追蹤且原請求資訊不足時不猜測伺服器是否完成。
- 專案重試使用目前選擇的模型、新的受限子程序與本次成果目錄，重新核對當下檔案；不覆寫、刪除上次成果，也不恢復舊工作副本或重播未完成腳本。

## 本機資料與後端

Message 新增選用的 project_activity、retry_settings、retry_context_index；只供本機加密保存及前端操作，對外 messages 仍只送 role／content。retry_settings 保存模型別名、模式、skills 與本機附件 ID，沒有 Token。API 路由、Bearer 登入與伺服器任務格式不變。

## 併入的 UI

專案路徑移到標題下；側欄名稱、＋新對話、齒輪。齒輪管理名稱、匯入與移除；移除選擇對話去向，均不刪文件。匯入使用原生選檔，全文框有邊框和貼上提示。VNC 更新頁集中在「機台管理」左側按鈕開啟的對話框，關閉時取消取得並嘗試登出。細節保留於先前兩份 PENDING 文件。
