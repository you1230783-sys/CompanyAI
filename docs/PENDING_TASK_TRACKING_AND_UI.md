## 任務查詢

- 一般對話工作控制器對每個request_id分別累計GET失敗。連續三次相同HTTP狀態（包含404與其他非2xx），或連續相同的網路／回應格式錯誤，才檢查模型服務。POST提交失敗及取消失敗不算GET次數。
- 達到門檻的當輪使用目前登入憑證呼叫既有models端點，要求HTTP200且模型清單可解析、驗證成功。同輪多個任務共用一次檢查；不以啟動時的模型快取判定正常。
- 模型服務不正常時繼續既有退避；任務GET成功就清除計數，不同錯誤重新從1開始。由by-request改用task_id時也清除；晚到的舊路由回應忽略。一般健康的queued／running不因停留太久而停止。
- 正式TaskStatus回failed／cancelled是已確認終態，仍立即收尾，不追加三次GET。專案代理自己的有界重試／checkpoint政策及附件轉檔工作未變更。
- 滿足條件時先保存已收到的回答片段與本機停止狀態，再解除等待。沿用DPAPI任務保存，重新啟動不再輪詢已停止工作。停止原因保留在任務卡；晚到的SSE、提交／查詢結果不能復活任務。
- 自動停止不額外查詢或取消伺服器，也不另建request_id重送；伺服器可能仍在執行。手動「停止追蹤」維持原來另行嘗試取消的行為。

維護位置：`src/jobs/polling.rs`保存結構化HTTP錯誤與三次判斷，`src/ui/work.rs`處理當輪健康檢查、事件及持久停止；`Task::validate_status`共用身分／結果核對。
