# 0.8.47 前置設計紀錄：參考線、偏好詢問、設定與日期

本頁保留先前「只修改來源」階段的設計、測試及用量分析。使用者後續已授權合併0.8.47編譯、完整NSIS與Git發行；本版最終狀態以 [VALIDATION_0_8_47.md](VALIDATION_0_8_47.md) 為準。

## 行為

- AI 工具 `set_chart_reference_lines` 對現有圖號整組設定最多 10 條參考線，空陣列清除。每條含實體 axis=x/y、value、name、#RRGGBB color。0–200、200–500、其餘的散佈圖例子是在 X=200、500 標線；其他分段由原始參數欄的新值第一筆座標判定，不推算未觀測到的切換時間。多於 10 處須明示限制、選擇或分圖，不偷偷省略。
- 類別軸使用從零起算的位置，數值軸使用顯示單位。先完成座標轉換再標線；後續改座標／缺值位置時，參考線維持固定顯示座標，需一併核對。原始點陣、資料明細、來源與既有 PNG 保留。圖表編輯器可改、刪線，還原則回到 AI 基準。已保存的使用者呈現設定優先。
- 多時段而排版不明時由 AI 用既有 ask_preference 問同圖加線／分圖。UI 固定提供「其他（自行輸入）」，空白其他不能送出。先做資料核對等獨立工作；需要答案而尚未回覆時採已公告預設，交付時說明。明確排版不重問，欄位／單位／授權不能靠偏好預設猜測。模型是否在各種自然語言下正確詢問，仍需公司實測。
- 設定頁分一般（登入、外觀、通知、服務版本）、操作（快捷鍵、使用行為）、進階（VNC、本機資料、診斷）。切換保留輸入草稿，支援方向鍵／Home／End。診斷任務清單改可見列表，新增上一輪／下一輪／查看最新；刷新保留所選輪數，用請求序號拒絕較舊回覆。另修正完成專案的摘要Task遮住逐輪journal的路由問題：優先讀專案紀錄，保留對話綁定核對，不因讀取錯誤降回摘要。
- 錯誤碼、詳細錯誤與獨立匯出見 [ERROR_CODES.md](ERROR_CODES.md)。原生 Windows 儲存對話框及 DPAPI 路徑本輪尚未執行驗收。

## 今天日期偏移調查

Windows 讀取方式與現有週一計算未見加七天錯誤，週報與 Outlook 快捷已有本機日期；一般專案和普通聊天缺乏同等明確依據。新增共用 Windows 日期來源，在新模型請求送入公曆日期、星期、ISO週年／週次及本週一起迄。普通聊天仍只送本次提問，另加一則本機日期 system 訊息，不重新攜帶聊天歷史。

新專案任務另保存最初提問日，跨日續跑不漂移原來「今天」的範圍；本輪使用者明確日期優先。舊 checkpoint 沒有最初日期，不杜撰。舊文字協定的技能目錄改另附短 system，避免新增工具後跨越原有單則64KB上限。日期只在每天變動，不加入每秒時間戳；已提交／結果未知的請求仍查原快照，不改寫後重送。根因尚不能單靠用量紀錄證實，模型是否採用本機依據仍待真實任務確認；如果 Windows 時鐘本身錯誤，需先校正 Windows。
