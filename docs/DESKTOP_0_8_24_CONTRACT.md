# 0.8.24 可選長文件閱讀筆記

取代 0.8.22／0.8.23 的「三次閱讀或六次工具操作」提示。一般聊天、後端路由與 `.lmai` 磁碟格式不變。

## 觸發與清零

- `read_file` 與 `read_document_section` 依同一相對路徑（忽略大小寫、統一分隔符號）及目前文字版本共同計數。只計成功新增閱讀區間的操作；原 operation_id 重播、讀過的區間、失敗不計次。
- 每份文件獨立；閱讀 A 三次及 B 兩次不構成五次。非閱讀工具不觸發也不累加。
- 第五次有效閱讀後，若仍未覆蓋完整文件，下一輪 messages 才載入 `src/projects/reading_note.md`。該文件版本只提示一次，不因模型忽略而每輪重送，也不增加專用模型請求。
- 以已讀區間聯集涵蓋 0 至 total 確認讀完，再將該文件計數清零。跳讀最後一段但中間有缺口不算完成；第五次恰好讀完時不提示。來源版本變更會重設該文件區間、計數及提示資格。
- 非持久計數，任務結束即釋放；完整文件與任務摘要仍以既有 `.lmai` 流程保存。

## 模型可自行決定

可選技能明確允許直接讀下一段，不需回應提示。若有需要，可用 `update_document_note` 摘要已完整讀過的段落，或在正常 JSON 同層自願附 `progress_note`。不要求每個分段都寫筆記；讀完一份文件後依既有文件摘要流程處理。

`progress_note` 維持最多 2000 字；有新工具歷史才接受更新，不以舊次數門檻限制。它是整體任務的累積摘要，不能把尚未執行的工具記成成功；來源版本變更仍使舊筆記失去精簡資格。

略過筆記不視為錯誤，不增加修復次數，不停止閱讀。既有 JSON 修復、60 次工具／80 次模型／30 分鐘、120 KB 軟門檻／240 KB 硬門檻保留。沒有足夠摘要時不刪未摘要證據，超過硬預算才明確停止；可選提示不是無限上下文保證。

## 網頁與交付

HTTP 仍為背景 Chat Completions、`skills:false`，按需技能由桌面放入 messages，不新增路由或欄位。內部進度不新增通知。

0.8.24 交付原始碼、EXE 與簽署清單；使用 v142 和空 Cargo 快取驗證，不重製 NSIS／ZIP。公司模型是否更穩定仍需實際閱讀測試。
