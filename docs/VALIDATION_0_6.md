# 0.6 驗證與公司驗收

契約見 [DESKTOP_0_6_CONTRACT.md](DESKTOP_0_6_CONTRACT.md)。契約先行發布供網站同步開發，EXE 交付結果以 `offline/verification.json` 的時間與版本檔為準。

## 本機測試範圍

- Rust 單元與 loopback HTTP 測試：模型 query 對附件副檔名的影響、404 任務停止後解除等待並保存、晚到狀態不復活、通知本機清除防重播。
- 全站鈴鐺 mapping、opaque ID 路徑編碼、Authorization／X-Client-Version、分頁、已讀更新、deleted_ids、游標 410 後完整同步、失敗保留快取、第一份快照靜默、重播去重、401／403／404／429／500 與連線失敗。
- 通知 URL 的部署前綴與跨站／危險 scheme 拒絕；伺服器錯誤本文不回顯 Token。
- Outlook 本機日期範圍、JSON 工具白名單、授權邊界、批次外郵件 ID／未知工具拒絕；提示詞不含 EntryID／StoreID。
- 既有 WebSocket 連線、喚醒、關閉／取消測試保留；全站來源在相同喚醒事件中另做 REST 同步。
- 已檢視本機瀏覽器的多封 Outlook 介面與通知合併面板；這是同份 UI 的預覽，不等同公司 Outlook COM 實機驗收。
- WebView2 自我檢查包含多封清單／全選、六種日期按鈕、通知來源／escaping、設定外部點擊關閉，以及既有 Markdown、串流、附件上限、快捷鍵。
- 完整交付流程仍須使用 v142 x64 探針、fmt、Clippy、Rust 測試、release 與 WebView2 自我檢查；並以 ZIP 內工具鏈、空 Cargo 快取及 `--frozen` 重建。

## 公司仍需實測

1. 網站部署 Token 鈴鐺 API 後，桌面與網站互相標記已讀／全部刪除，驗證同一資料庫與使用者權限；包含刪除 tombstone 及游標到期。
2. 真實 WebSocket 喚醒、斷線重連、恢復前景同步；429 退避與 401／403 停止重試。氣泡失敗不影響通知中心。
3. Classic Outlook 的多選與日期篩選、不同信箱 StoreID、移動／刪除原信後匯出失敗，以及公司 Object Model Guard 或防毒提示。本機沒有實際操作公司 Outlook，不宣稱 COM 實機驗收通過。
4. 勾選自動補充後，模型依指定 JSON 請求 MSG，App 自動匯出、上傳、等待轉檔及最終整理。驗證中文主旨、圖片、Office 附件及大檔限制。
5. 文字模型與圖片模型切換後的規則查詢、不相容附件提示，包含 MSG／PDF 轉檔後產生圖片的後端處理政策。
6. 上述流程中停止、關閉 App、斷網及強制結束，確認不再自動存取新郵件，不把完成結果加到其他對話。
7. 完全退出舊版後開啟新版，檢查檔案總管 EXE、視窗標題列、工作列、Alt+Tab 與系統托盤均為使用者提供的貓咪圖案；在 100%、150%、200% 縮放下檢查透明邊緣、還原／退出與 Explorer 重啟後的托盤圖示。未取得桌面外觀截圖前，不宣稱這些外觀驗收通過。若既有釘選捷徑仍顯示快取的舊圖示，可取消釘選後重新釘選新版。

## 已知邊界

- 本版不做任意本機檔案／UNC／RAG 工具，只開放本批已授權的 Outlook MSG 匯出。
- 初篩／COM 階段為本次 App 的互動流程；停止不一定能立即中止正在等待的 COM／HTTP，但不再進入下一步。退出後不自動恢復郵件授權。
- MSG 匯出瞬間需要明文副本，正常完成／錯誤路徑會清理；若程式或電腦強制終止，`outlook-exports` 可能留下副本。目錄位於目前 Windows 使用者的 App 資料目錄。
- 初篩每批最多 50 封；MSG 自動補充最多 20 封，仍受後端更小的數量／大小限制。不會自動上傳未勾選的郵件。
- 全站通知快取是網站資料的可同步副本；操作失敗不假裝網站已讀或已刪除。AI 通知清除仍是本機動作。
- `停止追蹤`／`移除任務` 不保證 server 取消成功，也不刪除對話。適用取消路由 404 或請求結果未知時解除本機等待。
- 網站尚未部署的新 API 回 404 會顯示未提供服務；不能只靠桌面變更宣稱已整合全站鈴鐺。
