# 0.8.27 長任務與異常續接

專案每段執行時間由 1800 秒延長至 7200 秒。沿用每段 60 次工具／80 次模型回覆；按「繼續」後重新計時、計數，保留既有工作副本及操作去重資料。

## 可以暫停的狀況

- 工具／模型次數或兩小時時限到達。
- 已完成模型回覆為空白、無效格式，有限修復次數用盡。
- 連續八次沒有有效進度，或上下文文字預算已滿。
- 原模型請求仍待完成，或連續三次 GET 無法確認狀態。

成功寫入 DPAPI checkpoint 後，對話標記 project_paused，前端以「繼續」取代「重新再試一次」。不得以模型自行聲稱已保存作為按鈕依據。暫存失敗仍回報失敗，不顯示假成功。

## 原請求查回

暫存新增可選 pending_model（Task）欄位，包含原 request_id、已知 task_id／狀態／結果及請求內容；不含登入 Token。0.8.26 checkpoint 未提供此欄位時視為無待查請求。

續接仍核對帳號、專案、對話與文件版本。若有 pending_model，先查回原 ID，不呼叫提交 POST；即使連續 404 也不換 ID。查回 completed 後才解析及執行工具。若在完成回覆到達時剛好超時，保留已驗證完成回覆，下一段直接處理，不丟棄、不重新要求模型生成。查回仍失敗則再次暫存。

本機工具不會在執行中被時間上限強行中斷；每輪／操作邊界檢查時間，工具回傳後才保存實際結果。因此慢的單一 HTTP／COM 操作可能使實際暫停略晚於兩小時。單一工具及 HTTP 既有 timeout 不改，後端／反向代理的時限仍須各自設定。

## 不可直接續接的狀況

使用者取消、伺服器取消／失敗終態、回應識別碼或契約錯誤、未知本機操作、檔案版本／授權核對失敗，仍停止，不重播。連續三次工具失敗與成果驗證失敗維持既有停止流程。這些狀況不因「有紀錄」就當成可以安全恢復。

舊版已因 30 分鐘停止且沒有 .resume.dpapi 的任務不能補造未儲存狀態；已發布成果仍在原資料夾。0.8.26 正常上限暫停檔可以續接。

只交付 0.8.27 EXE、簽署清單與原始碼／文件；Office COM、工具 schema、一般對話及 NSIS 不變。
