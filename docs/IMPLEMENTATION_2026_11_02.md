## 九項範圍

1. 重複成果偵測：依工具、來源與有效參數辨識重複計算／出圖／綁定，跨上下文整理保存；明確的使用者新指示允許重做。不能僅因新操作 ID 或新檔名認定有進展。
2. 交付清單：任務需求綁定可查的成果，區分待辦、草稿、已保存、待核對及無法完成；原生資料決定檔案狀態，模型不能自行宣稱已交付。
3. 條件卡：使用者可檢視與修改任務條件；補充版本跨 checkpoint 保留，條件更動提示既有成果需核對。
4. 定點修改：選取回答／比較區塊／圖形節點，帶入原對話、成果版本及來源的修改草稿，先由使用者送出。
5. 失敗接續：依真實任務狀態提供現有安全續接入口、保留成果及補做草稿；不重播未知寫入。
6. 成果中心：依任務分組、標記目前採用版本、顯示來源變更、成果狀態及可用的本機圖片預覽。
7. 流程表單：從已保存的參數插槽產生輸入表單，驗證類型及必填，列出步驟；送出前保留草稿與原生流程核對。
8. 能力提示：依模型／已提供工具顯示適用功能與替代路徑，避免要求未提供的 Python 套件；不擅自換模型或宣稱未核對的環境可用。
9. 工作偏好：使用者明確保存的個人偏好、專案覆寫與清除，任務開始保存有效快照；本次指示優先，不擴張檔案權限或載入公司內資料。

## 同輪追加：工具歷程、專案收合與來源筆記

使用者已同意實作並先編譯驗證，仍等 CAD 完成後才進版與 NSIS。

- 重連等待每次只新增一筆歷程；等待期間仍每 100 ms 檢查停止，不再每秒寫入倒數。
- 不再丟棄第 120 筆以前的工具歷程。介面以每頁 120 筆顯示，可查看較早／較新／最新頁；checkpoint 保留完整歷程，續接時接在原歷程後。整體 checkpoint 仍有明確容量限制，超限會回報，不靜默刪除前段。
- 每個專案可獨立收合／展開對話；原生保存狀態，執行中的任務也能收合，不影響目前對話或背景任務。
- `op_0001` 等短 ID 是程式分配的查詢別名，限同一任務並隨 checkpoint 保存；新任務另有自己的對照。內部操作冪等鍵仍使用完整 ID；不採 UUID 前綴匹配，不猜歧義。工作紀錄索引新增來源路徑，圖片比較保留第二路徑。
- 沿用累積閱讀 Notebook，擴充原件的 Office／PDF 文字閱讀及圖片辨識；Outlook 沿用已有逐信摘要、草稿與授權機制。結構化 Excel／LOG／計算結果仍走各自精確資料契約，不把數值資料集換成文字摘要。
