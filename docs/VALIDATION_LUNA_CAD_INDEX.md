### 已定位的影響因素

第 16 輪原始請求仍有正確的選孔筆記、snapshot_id 與 revision；因此不能說所有記憶被刪掉。另一方面，「本機分析概況」仍把第一次失敗的快照列為未解決錯誤，雖然之後已成功。

程式檢閱顯示 `analysis::State::observe` 對錯誤工具以通用方式記錄 failed，但成功分支沒有 CAD snapshot 對應處理，無法以成功結果取代此舊錯誤。這是可重現的狀態不一致；它可能誤導模型回頭修復，但不能只憑單次模型行為斷言唯一因果。

## E：固定 CAD 程序內批次匯出原型（2026-10-17）

使用者要求先驗證能否加速。新增可重現的測試工具與固定 LISP，尚未接入產品 Broker／CAD runtime；本節沒有執行 Rust 建置、進版、封裝或推送。前一階段讀取提示／600 秒的原始碼保留，但其建置與 GUI 驗證已中止，不能把本節當作該階段的驗收。

### 呼叫方式與資料範圍

- 2008：實際 `Document.SendCommand` 不存在；`Document.EvaluateLispExpression` 回 E_NOTIMPL。安裝目錄原廠 `Api/sds/IcadTLB.h` 提供 `Application.LoadLISP`，實測此入口可以執行固定唯讀匯出器。
- 2022：透過 `Document.SendCommand` 載入同一份固定匯出器。2008 的 LoadLISP 可能先返回，所以兩者一律等待檔案內的完整結尾，不把 COM 返回當作完成證據。
- 匯出器以 `ssget "_X"`／群組 67=0 取得模型空間主圖元，再於 CAD 程序內 `entget`。只匯出固定群組白名單：Handle、類型、圖層、顏色、線型／比例、文字、主要座標、半徑、註解與剖面相關數值等；保留重複群組，不宣稱完整 DXF／圖面內容。
- 以 JSONL、nonce、完整結尾及數量／Handle 唯一性核對；非有限值、截斷、錯誤 nonce、重複 Handle 及 DBMOD 不一致都拒絕。實數以 `rtos` 16 位小數輸出，避免預設 `prin1` 精度損失；此次 Windows 環境使用 CP950，無靜默替換解碼錯誤。
- 匯出沒有執行繪圖、Regen、Save、Close 或圖面系統變數修改。固定建立助手另行在自己新建的空白圖內產生壓力測試資料，建立耗時不計入讀取。

### 重現與後續整合

使用 `.build/cad-runtime-stage.txt` 指定的鎖定 `runtime/python.exe`，命令例如：

```powershell
python.exe -I -B tools/cad_bulk_probe.py --version Icad.Application.1 --name Drawing5 --compare-handles --check-sample
python.exe -I -B tools/create_cad_bulk_fixture.py --version Icad.Application.1 --lines 20000
python.exe -I -B tools/cad_bulk_probe.py --version Icad.Application.1 --name bulk-20000.dwg --check-fixture-lines 20000
```

`--open-test-path` 僅允許 `.build` 下合成 DWG，供另一版本唯讀開啟相同檔案。`tools/test_cad_bulk_probe.py` 的 6 項協定完整性回歸已通過。最終解析器另重新解析上述全部實測輸出，確認收緊檢查後仍能接受真實資料。

後續必須處理：資料轉換至原有索引 schema、OCS／WCS、傳統折線子圖元、圖塊／屬性／外參及未知物件、編碼選擇、鎖定且可信任的匯出器部署、工作檔完整性、取消／進度與修改前 revision 一致性。原有修改前完整 COM 快照及修改後核對仍會耗時；只替換首次讀取不足以保證整個修改流程都快。
