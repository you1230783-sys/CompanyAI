# 介面與串流修正

## 顯示與操作

- 上方標題列縮為 48 px，移除不必要的標籤與附件規則說明；上傳時仍依目前模型 capabilities 檢查格式、大小及合計數量，規則取得失敗仍會提示。
- 舊格式回覆含有編號正文與回答重點章節時，只將已辨識的來源、信心、限制章節放入預設收合的「來源、信心與限制」。不要求固定順序；來源後再出現的正文、重點及同級／上級未知標題保持可見。支援英文大小寫、中英文冒號、編號 Markdown 標題、編號清單與有編號的粗體段落，冒號後可直接接內容；沒有編號的關鍵字不觸發解析。章節內較低層級的子標題仍屬於原章節；普通回答、程式碼、引用或巢狀清單不觸發制式收合。展開可閱讀原內容，複製仍使用完整原文。
- 舊格式標籤依使用者提供的網頁規則：正文為 `answer / content / 回答 / 內容`；重點為 `keypoint / key points / keypoints / 回答重點`；來源為 `source / sources / references / 引用資料庫 / 內容引用處 / 來源 / 來源摘要`；信心為 `confidence / 信心度`；限制為 `limitation / limitations / 限制 / 回答限制`。
- 新版結構化回覆優先讀取 `response_payload_json`（也接受直接結果物件）的 `answer`、`sections.key_points / sources / limitations / confidence` 與 `citations`。正文與重點直接顯示，其餘及引用文件放入可展開區，空欄位不產生空標題。結構化正文不套用關鍵字收合，外層 confidence 不覆寫 sections.confidence。只有缺少有效結構化結果才使用前述舊格式備援。
- 背景與串流完成後共用同一解析；串流期間維持既有 delta 文字，完成後由 REST 結果補齊結構化欄位。本機歷史保存這些顯示欄位，複製及後續對話包含完整正文／重點／來源／信心／限制／引用。支援形式及欄位界線見 [結構化回覆契約](STRUCTURED_REPLY_CONTRACT.md)。
- 進入任務後切換到其他頁，清除已完成且已保存回答的本機任務卡。失敗、取消、進行中或尚未保存回答的任務保留；不刪除對話或伺服器任務。
- 進入通知後切換到其他頁，將 AI 通知標記已讀並同步，同時請求全站通知 ReadAll。若網站同步或個別操作正在進行，等待結束再送出；網站回覆成功才更新網站通知的本機狀態。
- 設定新增深色模式，使用灰藍背景而非純黑，包含內容區、側欄、設定、輸入欄與標題列，偏好會保存。舊偏好預設維持淺色。
- 設定的「本機資料」明示：伺服器仍保存已提交的資料，本機清除不等同刪除伺服器資料。

## 串流契約

以下為網站格式，所有事件以空行結束：

```text
event: start
data: {"event":"start"}

event: tool_status
data: {"event":"tool_status","status":"started","tool_name":"search_session_documents","arguments":{}}

event: tool_status
data: {"event":"tool_status","status":"completed","tool_name":"search_session_documents","result":{}}

event: delta
data: {"event":"delta","text":"已收到的文字"}

event: done

```

`start` 也可省略 data。工具狀態在首段文字之前即可顯示；名稱與狀態使用安全純文字，不硬編碼中文工具名稱。畫面顯示最近一次狀態，arguments／result 不傳入前端、不保存為工具紀錄。OpenAI 的 `choices[0].delta.content` 與 `[DONE]` 繼續支援。

串流中斷時，已收到的文字保留並加上不完整提示；本機加密歷史與任務紀錄保存這段內容。REST 仍是完整結果的依據，取回全文後取代同一筆部分回答。若任務最終失敗或停止追蹤，部分回答仍可在對話中閱讀。這是連線中斷處理，不保證程式被強制終止瞬間尚在記憶體的每個 delta 都已落盤。

## 驗證範圍

Rust 測試包含具名事件與 OpenAI 格式、UTF-8 分段、工具名稱與資料隔離、部分回答序列化／還原／取代與去重、任務清除條件及舊設定相容。Loopback HTTP 測試混合兩種 delta、工具開始／完成與具名 done，並模擬斷線後 REST 取回。

WebView2 自我檢查涵蓋中英文回覆格式與別名、重排／重複章節、編號清單、子標題及未知標題邊界、程式碼／引用／巢狀清單不誤判、串流到完成後的內容一致、點擊展開與重繪保留，以及完整原文不變。亦保留頁面離開命令只送一次、附件說明隱藏、深色背景、首段文字前工具狀態與完成更新，以及不完整回答警示。2026-09-23 本機修正驗證見 [回覆章節驗收](VALIDATION_REPLY_SECTIONS.md)。

0.8.11 另以使用者提供的單行英文五段全文驗證串流轉完成、展開區塊實際具有可見高度、複製及歷史重繪。只有正文的完成 payload 會在正文相同時補空欄位；正文不同或欄位衝突時另存可展開原文。此規則補充前述結構化優先流程，詳細條件見 [回覆契約](STRUCTURED_REPLY_CONTRACT.md)。

公司仍需以真實串流、通知服務及 Outlook 2024 的 Exchange／PST 帳號實測。本機模擬與介面檢查不代表公司服務已驗收。
