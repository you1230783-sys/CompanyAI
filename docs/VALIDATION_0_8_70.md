# 0.8.70：同圖分段計畫

## 變更

新建 CAD 先保存短方案，再以每段 1–20 項操作累積同一份本機計畫。暫存階段不連線 CAD；全部齊備才合併成原生計畫、建立一張 DWG、存檔重開。模型不必重新輸出整張圖的幾何參數。

- 區段以穩定 ID 和 `plan_revision` 管理；相同 ID 按最新版本整段替換，其他區段不變。完全相同重送不重複累加，過期修改拒絕。
- 完整參數保存在既有加密 checkpoint。整理上下文或續接仍保留計畫；模型接收區段目錄及最近四段的精確資料，合計最多 32KB，超額明列省略 ID，原計畫不刪除。舊段可按需查回，已完整常駐的段不再公告查詢入口。
- 每圖最多 40 段、400 項、500KB；原生圖元預算 4000 及十分鐘期限保留。舊直接 `cad_draw` 仍最多 100 項；不靠多次建圖追加同圖。
- 成功後只回有界交付摘要和警告，完整原生報告保存在本機。部分或未知失敗仍保留原生狀態，不自動重畫。指令合併到幾何之後，模型座標不被程式改寫。

本版亦納入先前隔離驗證的 ICAD2008 原生 Undo 相容、ANSI 批次匯出、Unicode 檔名核對、縮放範圍備援、查詢上下文及具體欄位拒絕診斷。舊版原生 Undo 備援仍僅支援圓半徑與允許的 ACI 顏色修改，不能推論支援任意編輯。先前證據見 [修正紀錄](PENDING_CAD_Q2_OPTIMIZATION.md) 及 [圖型矩陣](VALIDATION_CAD_USER_SCENARIOS.md)。公司最初的原圖 revision 誤拒絕仍未以原檔重現。

### 真實圖面問題

- 2008：缺少原生尺寸。大門聲稱 x3500–4500 有開口，但原生線仍連續；廚房門實際只有 500mm，樓梯入口亦有橫牆線，不能保證通行。部分「衣柜」字形顯示問號。兩組十一條踏步以 x+10000 對應，並未驗證實際樓高、平台與淨高。
- 2022：缺少原生尺寸，房間／衛浴線框封閉，沒有門窗。「楼梯」在真窗口顯示「?梯」，衛浴藍色家具低對比。陽台實際在 y20000–22000 上側，答覆卻稱左下延伸，描述與圖面不一致。
- 2008 詢問後收到每層 8m×12m 及一樓廁所補充；2022 沒有詢問，模型自行假設 12m×10m，因此不能將未送出的角色補充當成 2022 已知要求。兩案配置不同，不做設計或速度的一對一比較。

兩份 DWG 都做了獨立原生讀回、實際 CAD 全圖及局部目視；僅調整視野，沒有修圖或補存，磁碟 SHA256 不變。不是只依模型「已完成」文字判定。

## 除錯歷程

第一候選根 `.build/cad-user-segment-b6c0ac42f26a4f1fbc15b133bc3bd17a` 的 2022 曾以五段 58 項生成 78 圖元，零次 length，但二樓標籤漏位移、缺尺寸，結果仍 ISSUES。2008 在四段 75 項後反覆查牆線與家具：整理後只有最近一段工具原文，另一段精確資料不在當輪上下文。這是產品工作集缺漏，不能歸咎模型或稱雙版通過。

在沒有新 DWG／CAD 報告的階段取消待回覆並核對後停止自有 runner；原 CAD 文件不動，原證據及晚到未執行回覆保存。修正成目前的四段／32KB 精確工作集，查回時還原 `line_style:null` 的公開傳輸形狀，再完整建置與雙版重測。前候選不改判，最終候選結果如上。
