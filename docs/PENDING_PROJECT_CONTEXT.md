# 待發行：專案跨任務上下文

## 原因

原先同一對話的新任務保留最近三輪完整要求與答案，另帶最多40KB專案記憶。
單次任務的工具歷程壓縮不會主動移除這些起始答案，長診斷容易重複帶入。

## 本次修改

- 最近三輪使用者要求、連續補充及本次要求保留原文；不由摘要重新解釋授權。
- 有任務索引的助理答案改成狀態與read_task_result參照；摘要只出現在專案記憶一次。
- 任務記憶附實際狀態、摘要最多600字、完整成果路徑最多8筆；省略數與摘要截斷明示。完整資料仍保存在加密任務紀錄。
- 歷史與記憶共用5000估算token預算，預留說明欄位；近期使用者原文或無索引答案超過預算時保留並明示例外。本次要求、系統提示、工具定義與本次工具結果不算在此歷史預算。
- 優先近期／相關任務，再方法與一般筆記、文件摘要；完整項目加入預算，不裁切JSON／檔案路徑。方法筆記不重複送入一般筆記。
- ASCII每4字元、非ASCII每字2tokens僅為本機估算，並非精確tokenizer，也不是API硬上限。
- 加密任務診斷cross_task_context及進度訊息分別列本次要求、歷史、記憶估算量。記憶內context_budget另列預算例外。
- finish／ask_user鼓勵同輪附200–400字交接摘要，不新增額外摘要推論；舊版沒有摘要時沿用明示為節錄的備援。依賴先前選項／精確結論時查回原文，不無目的讀完全部歷史。
- 原生回覆已通過身分檢查，finish_reason=length、content空白且沒有工具呼叫時，封存工具結果、精簡續接狀態並暫停。只有使用者繼續才再推論，不自動耗費第二次相同輸出額度。非空截斷與非原生回覆維持既有修復流程。

## 界線與待驗證

本輪只修改原始碼、整理格式；未新增或執行測試，未編譯／進版／打包／推送。
原始歷史不刪除；最近三輪以外的要求仍透過既有任務索引／筆記查回，並未新增永久限制抽取器。
進行中已暫停任務沿用原checkpoint，不把本次新任務估算誤報為checkpoint已被重新摘要。
發行前需驗證長答案連續三任務、重試上下文、舊版無摘要、等待使用者選項、長原始要求超預算、方法去重、原文分頁查回及空白length暫停／續接。
實際輸入與輸出token改善仍需公司模型實測，不保證整份請求低於20000tokens。
