# 錯誤代碼與診斷檔

本文件對應 0.8.47。代碼用來定位問題類別，「可能原因」不表示已確認根因。無法辨識的錯誤使用 99，不把所有 Windows 例外都判成權限問題。

| Error Code | 問題 | 可能原因／處理方式 |
|---|---|---|
| 01 | 選擇或建立專案資料夾時權限受限 | 資料夾 ACL、公司保護軟體、網路磁碟登入帳號；選可讀寫位置，確認權限。只有專案資料夾操作加上明確存取拒絕證據才用此碼。 |
| 02 | 其他檔案操作權限受限 | 來源或輸出位置不可讀寫；核對帳號與加密文件開啟權限。 |
| 03 | 找不到檔案／路徑 | 來源已移動、刪除，UNC 或映射磁碟斷線；重新選取來源。 |
| 04 | 檔案被占用 | Office 或其他程序持有檔案；先儲存、關閉占用程序後重試。 |
| 05 | 網路失敗／逾時 | 網路、代理、服務等待；檢查連線，結果未知時先查原任務。 |
| 06 | 登入／授權問題 | Token 到期、帳號權限、HTTP 401／403；確認帳號並重新登入。 |
| 07 | AI 服務暫時失敗 | AI_BACKEND_ERROR、HTTP 502／503／504 等；依畫面等待重試或稍後繼續。 |
| 08 | 資料格式不符合預期 | JSON 格式、回覆結構或來源格式；檢查資料，持續發生時匯出資訊。 |
| 09 | 本機紀錄讀寫／解密失敗 | 磁碟空間、使用者變更、紀錄損壞、資料夾權限；保留現有紀錄。 |
| 10 | Office／Outlook 操作失敗 | COM、應用程式啟動或文件狀態；確認桌面版應用程式及提示視窗。 |
| 99 | 尚未分類 | 不能只憑底層例外名稱判斷原因；匯出詳細錯誤供維護者確認。 |

目前涵蓋介面回報、專案建立／執行／工具失敗、一般聊天提交與伺服器任務失敗。既有本機化操作提示會保留，底層 WinError／HRESULT／Traceback 改由診斷詳細資訊查看。工具交給模型的原始錯誤保持不變，避免影響修復、權限與重試判定。不是所有第三方崩潰都能捕捉；程式啟動前或程序突然終止的錯誤不保證有紀錄。

## 匯出方式

1. 登入後開啟「設定 → 進階 → 診斷」。
2. 按「匯出錯誤診斷檔」，在 Windows 儲存視窗選取 JSON 位置。
3. 直接把檔案交給維護者；不會自動上傳。

預設檔案是 `lmai-errors-v1`：程式版本、Windows x64、匯出時間、Windows 本機日期、最近 200 筆錯誤的發生時間（Unix 秒）、代碼、操作階段、處理建議與可辨識的標準數字錯誤碼。沒有帳號、對話、檔名、郵件正文、文件或工具參數。若歷史無法讀取，`log_status=unreadable_or_invalid`，不能當成沒有錯誤。

勾選「附加原始錯誤文字」會加入每筆最多 4,000 字的原始錯誤，可能含路徑或服務回覆。已知登入憑證及認證欄位會遮蔽，但仍請依檔案內容決定分享對象。這不是記憶體轉儲，也不會掃描整個專案。

錯誤歷史在應用程式資料目錄以 `errors.dpapi` 加密保存，不需先開 DEBUG；紀錄損壞不覆蓋舊檔，保存失敗會在畫面附註。JSON 來回紀錄（含正文）及 `lmai-usage-v1` 用量統計仍有獨立的查看／複製功能，不混進錯誤檔。

## 維護者判讀

先依時間、stage、code 和 technical_codes 對照失敗操作。只有附加 detail 才可能有原生例外；沒有 detail 時不能推斷具體檔案或完整原因。與使用者確認是否為同一版、同一來源、同一次操作；不要把逾時直接當成服務已取消。代碼對照由 `src/errors.rs` 維護，新增代碼時同步更新此文件。

## 0.8.49正常操作修正

單擊／展開工具歷史或時間只操作本機顯示，不送出通知read_event。使用者手動停止專案屬正常取消，顯示已停止及保留草稿，不產生Error Code 99。真正失敗仍保留原有分類與診斷；不能把未知的伺服器提交狀態當作已取消。
