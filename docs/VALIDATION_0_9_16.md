# 0.9.16 驗證紀錄

M10 已完成相關驗證、正式編譯、封裝及發布。公司模型與附件服務留待公司端驗收。

## 修改與界線

- 一般對話任一使用者訊息可編輯並重新送出，保存原版本、原草稿及後續回答。版本切換只交換本機歷史，不送模型或工具。舊格式以「原始版本」讀取。
- 本機網站聊天原本只送最新提問，由網站補上下文；新分支改以每次 request ID 建立獨立網站對話，送出選定完整快照。續問與手動重試沿用同一原則；原始版本保留原行為。未知結果仍查同一請求，不能建立新 ID 重播。
- 附件只從保留使用者訊息的原生 RetrySettings 識別解析，核對對話擁有權、到期與網站狀態；不帶舊尾段附件，不將 Token 傳入 WebView。失效時明確停止，提示另開對話重新附加，不默默省略。
- 專案已開始執行的訊息禁止原地編輯。最新且沒有請求／操作紀錄的提問可放回草稿。任一訊息可準備到該位置為止的交接摘錄，預覽確認後只建立新專案草稿，不移轉附件授權，不自動送出。
- 每個對話最多32個版本，沿用整份歷史32MB上限；版本來源、順序、長度與重複識別均驗證。執行中或有尚未送出的附件時，先完成工作再切換版本。
- 安裝器與 Python／CAD runtime 未修改。本版使用 scripts/Test-ReleaseInstaller.ps1 驗證實際交付包的安裝、更新、啟動與解除安裝；PID交接、失敗回復、runtime修復等完整矩陣見0.9.15證據，本版不重複宣稱已實測。

## 公司端驗收

請驗證真實模型是否只收到目前分支，以及公司網站是否允許仍有效的原附件Token在獨立分支網站對話使用。原生程式不新增網站授權；若網站限制跨對話附件，應明確拒絕並重新附加。公司模型品質、Office文件、CAD圖面與完整Python科學矩陣不列為本版已驗收。

- 第一輪正式EXE已走完分支／續問／手動重試，最後的「專案草稿不送出」測試仍使用新增手動重試前的固定請求數2，實際應為3，因此拒絕通過。改為在專案操作前記錄計數並核對操作後不變，另確認前三個請求確實為編輯、續問與重試。此為自檢期望修正；將重新編譯並重跑正式EXE。

- 修正自檢計數後，第二輪v142空快取frozen建置成功；正式EXE六組介面自檢、11項分支原生案例與Python／CAD runtime通過。正在封裝及執行候選安裝包驗收，推送來源供同提交CI。

- 契約補充：本機示範後端 src/demo/work.rs 的附件驗證要求 owner、conversation_id 與 ready 狀態一致，因此「狀態仍有效」不必然代表可在新的網站對話使用。分支原生HTTP測試只驗證客戶端的前綴／授權選取及狀態再查詢，不能當作公司後端跨對話附件能力證據。公司端若沿用嚴格綁定，帶附件的分支請求會被拒絕，必須在新對話重新附加；不擅自放寬伺服器授權。
