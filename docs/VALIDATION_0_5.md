# 0.5 本機驗證與公司驗收

後端路由與欄位以 [DESKTOP_0_5_CONTRACT.md](DESKTOP_0_5_CONTRACT.md) 為準；契約已先行提交供網站同步實作。

## 已執行的開發驗證

- Rust 測試涵蓋動態附件副檔名／大小／合計數量 20、Base64 區塊順序、DPAPI 附件暫存與串流讀取。
- loopback HTTP 模擬後端驗證原始二進位上傳雜湊、預約重試、queued／processing／ready、短期 token、帳號與 conversation 歸屬。
- 聊天測試涵蓋 background 202、重複 request_id 不新增工作、依 request_id 找回回應遺失的工作、SSE 中文 delta 與最終 REST 結果、SSE 缺少 DONE 後恢復查詢、取消。
- DPAPI 任務紀錄可重新載入並隔離 principal；歷史已寫入但任務尚未標為已套用時，再套用相同結果不會新增第二份回答。
- WebView2 自我檢查包含附件卡片、檔名作純文字顯示、串流 Markdown、閱讀上方時保留位置、在底部時跟隨、圖片貼上事件共用 20 個上限。貼上測試採 renderer 合成事件，不讀取使用者真實剪貼簿。
- 透過本機瀏覽器預覽檢視過聊天／附件卡片與任務面板。這是同一份 HTML/CSS 的預覽，不等同公司機器上的原生視窗截圖。
- 正式交付須通過 scripts/Prepare-Delivery.ps1：實際 MSVC v142 x64 探針、fmt、Clippy、測試、release、WebView2 自我檢查，以及包內 Rust／空 Cargo 快取／--frozen 的完整重建。結果見 offline/verification.json 與 offline/environment.txt。

## 使用方式

1. 登入後，桌面會讀取 capabilities。網站尚未部署時，保留一般純文字聊天。
2. 選「串流回覆」或「背景處理」，按迴紋針選檔，或在輸入框貼上圖片。文件＋圖片最多 20 個，實際格式與大小由網站提供。
3. 卡片顯示接收、等待上傳、上傳、排隊、轉檔、可送出或失敗。所有附件就緒後才可送出；只有附件也可送出分析。
4. 可按「估算時間」查看等待／處理／總時間。未知資料顯示未知，不當成零秒。
5. 工作送出後可切換／新增其他對話。同一對話有未完成工作時不接受另一個請求，最多同時追蹤 8 個聊天工作。
6. 任務面板可開啟對話、重新整理、取消；送出結果未知時，可用同一識別碼重試。不要另開一份相同請求代替重試。
7. 最小化會隱藏至系統托盤。托盤左鍵還原；右鍵可選還原／離開。視窗右上關閉及托盤離開會正常退出程式。
8. 程式退出不取消 server 已接受的工作；重新啟動、登入同帳號並取得能力後會恢復查詢。退出期間不會有桌面即時提示。

## 保存與邊界

- 已送出任務的請求、識別碼及狀態以 `jobs-<帳號及服務雜湊>.dpapi` 保存，與原 history.dpapi 配合去重。
- 工作資料依 server principal_id 隔離；一般歷史維持原本的 Windows 使用者本機保存方式。
- 原始附件只在等待上傳／待重試時保留加密區塊於 uploads/。確認 server 接收後清除；沒有成功接收完整的選檔需要重新選取。
- 尚未送出的文字草稿與郵件預覽仍只在記憶體，關閉或切換新對話不保證保存。已上傳的草稿附件狀態則屬於對應本機對話。
- 轉檔內容、圖片與上下文由 server 處理，桌面不做 OCR、文檔解析或工具呼叫。
- 圖示後續已換成使用者提供的貓咪圖案，EXE、視窗、工作列及托盤共用 assets/app.ico；目前驗收方式見 [0.6 驗證說明](VALIDATION_0_6.md)。

## 公司端仍需實測

1. 依真實後端格式上傳 PDF／Office 文件／圖片，包含大小邊界、20 個混合附件、轉檔失敗與 token 到期。
2. 在 Adobe、截圖工具、Office 等來源複製圖片後，在 App 輸入框實際貼上；不同來源可能提供不同剪貼簿格式。
3. 反向代理有無緩衝 SSE、heartbeat 是否每 15–20 秒送達；斷網、重連與 Token 換發後是否恢復原任務。
4. 真實持久 worker 重啟／多程序環境下的 idempotency、排隊優先權、取消競態及最終結果落盤。
5. Win11 上最小化到托盤、右鍵還原與退出、Explorer 重啟後圖案重新加入、完成提示點擊開啟任務面板。
6. 公司實際安裝的 MSVC／SDK 修補版、WebView2、Classic Outlook 與 Adobe PDF 相容性。

不能以 loopback 模擬測試宣稱上述公司系統已整合成功。模擬後端僅在記憶體保存資料，沒有正式持久 queue，也不做真實文件轉換。
