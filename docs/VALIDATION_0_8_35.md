# 0.8.35：進度筆記、LOG 定位與主輸入框

## 功能與相容性

- 執行中顯示最新 `progress_note`，結束後收進「查看工具紀錄與進度筆記」。首輪也可顯示；純文字呈現，不作 HTML 解譯。工作摘要與最終正文、複製內容分開，沿用既有 DPAPI 活動紀錄。
- LOG 技能把約略時間當成定位線索：先前後各 5 分鐘，命中後用檔名／版本／行號回讀確認真正起點；完整搜尋沒有候選才擴大至 15／30 分鐘。明確指定嚴格範圍時仍照原範圍。新增純時間後逗號分隔訊息的解析，無日期時不假裝已確認。
- 主輸入框提供下一輪提示（預設）、停止後新任務、完成後新任務。每個對話一則待送新任務，最多 16000 個 UTF-16 字元；等待時仍可補充目前任務，既有補充可在主輸入框修改或撤回。
- 待送文字先 DPAPI 落盤，才發出停止要求；舊 worker 的 Finished 到達後才接續。綁定原對話、專案、帳號與模型；切換畫面不影響原任務接續，也不清除另一對話草稿或誤產生標題。
- 暫停、失敗、等待補充、手動停止或重啟時保留待送訊息，停止自動啟動；可手動傳送／取消。排程轉成新任務時，在同一次歷史保存中清除排程並加入使用者訊息。新 run 使用原排程 ID。
- 前端核對 conversation／run／request 的原生確認才清除原文字，保留之後輸入的新草稿。過期送出、重複排程及保存失敗不自動改送其他任務。
- Cargo 依賴不變，保留 Cargo.lock、vendor 與 .cargo/config.toml。網站 API、工具數量（38）及工具參數不變；新任務依既有契約使用新 run／request ID。

## 測試界線

原生排程自檢由 `--self-check` 隱藏視窗執行，資料放在獨立暫存目錄，服務只用 loopback。舊 worker 的完成／停止是受控事件；新 worker 走正式 runner 執行緒，隨即取消並等待 Finished。另由既有 AppContainer、真實檔案鎖及 Office 測試驗證原生工具。這不等於公司模型／Outlook／Office 三者串在同一排程的實際聯測。

前一輪隱藏 Edge 載入原始 UI 的 21 項主輸入框檢查，以及進度筆記顯示／收合／複製檢查已通過；當時使用虛構任務與命令接收器，原始紀錄見 [LOG 與輸入框](PENDING_LOG_AND_COMPOSER.md)、[進度筆記](PENDING_PROGRESS_NOTE_UI.md)。本輪補上原生控制器與 EXE 自檢，不將前一輪 DOM 檢查冒充公司實機驗收。

近似時間搜尋是模型技能指引；真正事件辨識、公司加密檔案、實際郵箱、模型遵循程度與長時間穩定性仍需公司環境測試。24 小時政策延續 0.8.34，採控制時鐘與跨批 checkpoint 測試，沒有宣稱已連跑 24 小時。

本版只交付 EXE 與簽署清單，不製作 NSIS／離線 ZIP。Git 發布不代表公司網站已部署。
