## LOG 搜尋

- 約 10:00 上料先查 09:55～10:05，不把 `10:00` 填入字面關鍵字反覆搜尋；明確要求的嚴格時間範圍仍照使用者要求。
- 命中後以檔案／revision／行號／原文時間作錨點，回讀前後文，核對上料、判定或作動起點。報告區分使用者記憶與 LOG 確認的時間。
- 完整搜尋無候選時，依序擴大到前後 15、30 分鐘或調整原文已確認的事件詞；沿 next_cursor 續頁，不反覆從第一頁重跑。仍無法定位或多筆事件無法區分時彙整範圍並詢問。
- 原本已支援 `HH:MM`、`HH:MM:SS.sss` 與方括號的純時間行首。本輪修正末尾逗號分隔訊息，例如 `10:03:21.084, 上料判定`；日期依前文明確日期或可辨識檔名補足，沒有日期或跨日時不自行猜測。
- 工具參數與大小／分頁限制不變。指引改善搜尋策略，但模型遵循程度仍需公司實測。

## 主輸入框

目前執行中的專案對話提供三種傳送方式，一般聊天維持原流程：

| 方式 | 行為 |
| --- | --- |
| 下一輪加入提示（預設） | 沿用本次任務補充機制；已開始的工具先完成。最多 4000 字，待接收項目可在主輸入框修改或撤回。 |
| 停止目前任務並傳送 | 先保存訊息再停止；舊 worker 結束後啟動同對話的新任務，不併行操作檔案。 |
| 任務完成後傳送 | 先保存訊息，原任務正常完成後啟動新任務；開始前可取消排程。 |

每個對話先支援一則待送新任務（最多 16000 個 UTF-16 字元），等待期間仍可送下一輪提示。欲改排其他任務，先取消原排程；取消「停止後傳送」的排程不撤銷已發出的停止要求。

待送訊息與對話一起 DPAPI 加密，綁定原 run、專案、帳號及模型；新 run 使用排程 ID，清除排程與加入正式使用者訊息在同一次原子歷史保存完成。啟動前重新核對登入、版本、模型／帳號、專案授權與其他工作狀態。待送文字啟動前不放入模型上下文。

自動接續不切換畫面或清除其他草稿。原任務暫停／失敗／等待補充、手動停止、程式重開或啟動條件不符時保留文字，可按「現在傳送」或取消。重開程式不自動執行。

收到精確 conversation／run／request 回覆後才清除該次文字；另打的新草稿與其他對話不受影響。確認前禁用重複送出；任務剛結束而拒絕時原文保留，不改送至新任務。
