# 0.8.72：Mermaid、CAD 擴充與等待確認通知

本輪依使用者要求執行基本建置及功能針對性驗證，包含已開啟的本機 Strata。完整 workspace／長任務、公司服務及安裝生命週期未重跑；歷史版本的完整 PASS 不當成本版結果。

## 功能範圍

- 專案可從敘述、Mermaid 文字或唯讀程式碼產生圖形。離線 Mermaid 12.2.0、來源複製、縮放／全畫面、MMD／SVG／PNG 保存、來源版本與跨輪修改。詳細限制見 [Mermaid](MERMAID.md)。
- 原生多段線／圓弧、半徑／小角尺寸、新圖層、基本圖塊及有限 2D 幾何編輯；範圍見 [CAD 能力](CAD_CAPABILITIES.md)。不開任意指令／COM。
- 背景等待用戶確認時，Windows 托盤通知及工作列提示，按 request 去重，點擊回原對話。前景不重複提醒，不代答同意。
- 模型同時提出多個合法工具時，先要求依契約改成單一工具或 run_batch，不執行其中任何一個；未知工具、重複 ID 仍拒絕。

## 本機 Strata

使用實際專案 App／runner／WebView2 及 localhost 轉接，low、每輪輸出額度 20,000。僅合成檔案與私有新圖，未存取公司郵件或修改使用者圖面。不代答確認，不改寫模型工具參數。

隔離入口為 `--local-project-scenario <localhost連線JSON> <新App資料目錄> <情境JSON>`，情境最多8輪及有界的平面合成檔案，專案與WebView2資料分開。需要用戶確認就停止，不自動代答；`scenario-result.json` 完整結束仍明示須獨立審閱，不能單憑助理文字列成功。

最初 Mermaid 情境發現 WebView2 資料目錄與測試專案共用根目錄導致檔案鎖，以及多工具輸出直接中止。已分離隔離目錄並加入有界格式修復；失敗輪次保留，最終驗證另起新候選。每輪必須以加密 journal 的真實成功結果通過，不只看助理文字。

第二次情境已成功渲染及保存三種格式，但模型在上下文整理後反覆重讀同一來源與行號，尚未收尾；只停止該隔離測試程序，保留全部產物及追蹤。Mermaid 指引因此補上同 revision 的核對結論可沿用、已保存各格式後立即交付，以及 README 應使用一般文字讀取工具；最後候選重新編譯、封裝與實測。

再測證明只加指引仍不足：工具歷史移出後，最新圖源與原始程式沒有固定保留，模型會重新推測再回讀。已補上獨立有界工作資料，固定帶入最近圖源、已讀程式／短篇README的行號與版本、保存匯出紀錄。直接讀取與run_batch主程序提交均登記，整理歷史及checkpoint還原保留；數量／大小上限、舊revision淘汰及還原的針對性Rust測試通過。最後實測另用全新候選，不將先前未收尾情境列為成功。

2008模型情境另抓到圖塊成員的相容性問題：文件HandleToObject無法查回剛建立的圖塊內圖元，導致設定圖層失敗，已開始的私有圖停在未存檔狀態，沒有自動重畫。已改用建立時取得的原生物件並核對Handle；新增97項中的回歸檢查，禁止此路徑查回文件Handle，並將中文圖層與原生CENTER圖塊子圖元加入雙版存檔重開實測。錯誤原圖與診斷保留；最後另建隔離情境，不恢復失敗圖的寫入授權。

三輪 Mermaid 情境完成：靜態讀取合成程式碼並產生流程圖、讀回來源修改標籤與重試說明、另建 stateDiagram-v2。獨立核對來源 SHA256、based_on、原件不變與舊版保留，共 3 份 SVG、2 份 PNG；PNG 已目視。長標籤可能換行，複雜圖仍宜拆分。Mermaid 使用最後 CAD 大小寫修正前的候選實測；255 份 Rust／UI／Mermaid 指南與 Cargo／build 來源均逐檔 SHA256 核對未變，最後僅修正 CAD Python／runtime，雙版 CAD 另以最後發布 EXE 實測。兩份實際 EXE 雜湊記於公開摘要，不混稱為同一二進位檔。

2008／2022 模型情境各完成一份固定座 DWG。獨立重新開檔核對 120×80 封閉原生多段線、四個實際 INSERT 孔塊、Ø6 圓與 CENTER 十字線、三個指定圖層、R20 四分之一圓弧、120／80／90度真正尺寸及中文標題。半徑尺寸的原生中心、圓上點及量測值另外逐項對照模型原始分段參數，執行結果一致；唯讀覆核後 DWG SHA256 不變。

使用者意圖數值核對並未全部通過：2008模型將半徑尺寸圓上點四捨五入成(164.14,54.14)，中心為(150,40)，真正尺寸為19.996979771955555；2022模型使用(155.858,34.142)，中心為(170,20)，真正尺寸為19.9998081990803。兩弧本身均是R20。原嚴格R20檢查失敗紀錄保留，未放寬容差改稱通過；這是模型輸入的內容問題，並非原生執行把R20改小。固定原生情境則以精確點通過R20尺寸。2022的INSERT容器在0層，孔圓／中心線成員在指定圖層，符合模型原始參數；容器層的管理方式仍待人工審閱。所有模型內容問題列於公開摘要，圖面不能視為設計／加工核准圖。

後續模型使用順時針射線建立90度尺寸時，原生CAD以逆時針順序讀回兩端點，量測正確卻被逐點核對誤拒絕，停止於存檔前。已在建立前將小角射線正規化為逆時針，預期值仍由輸入幾何推導，不放寬讀回檢查。新增正反方向／重複驗證／錯誤位置的回歸測試，並加入雙版原生存檔重開情境；失敗圖仍保持未存檔，最後模型另用全新專案重測。

2008模型另使用混合大小寫圖塊名稱HoleBlock，原生INSERT.Name讀回HOLEBLOCK，原逐字比對在存檔前誤拒絕。自建圖塊名稱改依符號語意不分大小寫核對，其他名稱、座標、比例與屬性不放寬；不同圖塊名稱或錯誤比例仍有拒絕回歸。固定雙版原生情境也改用混合大小寫名稱，模型CAD另起新候選重驗，失敗私有圖保持未存檔。

功能通過不等於AI內容已證明正確：先前候選的概念狀態圖曾將「should_retry為假」的失敗路徑接到重試狀態，條件表達不完整，且遞迴呼叫行號寫13而實際在14。最後候選雖正確保留精確原碼，第一張流程圖仍將main.py函式入口寫第6行（實際第7行）、遞迴呼叫寫第11行（實際第14行），多處引用不準確。原始模型成果保留，未人工補圖冒充模型成功；本輪沒有通過AI語意／引用品質審查。讀碼圖的分支語意、引用與設計品質仍須人工覆核；本輪驗收的是實際讀取、呈現、匯出與跨輪來源版本保留。

CAD 本輪以原生資料核對為準；沒有完成 CAD 真窗口的目視驗收。中文字型、標註避讓、設計／加工與裝配須人工審查；資料通過不代表設計通過。非本輪功能的 COM BMP Export 輔助驗圖曾失敗，未當成已目視。
