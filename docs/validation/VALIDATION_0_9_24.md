# 0.9.24 私聊訊息驗證

## 訊息、收件與空間

- 文字以 Unicode 字元數限制 4,000 字。WebView 僅建立文字節點，保留 HTML、Markdown 及網址原文。送出前先保存本機加密記錄，重送沿用同一 UUID。
- 檔案選擇使用原生 JPG／PNG 選擇器，剪貼簿截圖沿用 Windows DIB 路徑。出入站圖片由 WIC 重新編碼為 JPEG，最長邊 4096 px、每張最多 10,000,000 位元組，移除 EXIF。只在選擇查看時以 JPEG data URL 交給私聊視窗。
- 每 20 秒安排一次 status，鎖定時只取狀態及回條。解鎖才逐筆取得訊息。保留加密本文及索引的寫透結果後才取得 ack 許可。上鎖期限若在保存期間到達，留待下次解鎖重抓及去重。無法驗證格式或寫入的訊息會留在伺服器等待處理。
- 同一訊息的資料金鑰只存於 DEK 加密索引，本文單獨加密。單則刪除及圖片清理先從索引移除該金鑰，再清理密文檔。批量時間清理同時移除訊息、時間及資料金鑰；保留不含時間的入站 ID 雜湊，避免伺服器重播復原已刪項目。索引讀寫上限 128 MiB。測試涵蓋應用程式目前使用的資料檔及索引。
- 鎖定時收到的回條以 DPAPI 暫存 UUID 與送達／過期狀態，解鎖後才寫入 DEK 加密索引。暫存沒有訊息本文、時間或好友身分。伺服器契約於 status 回應後即可刪除回條，極端情況下若本機同時故障，該次回條可能需要伺服器端協助核對。
- 私聊通知預設只顯示「收到新訊息」。鎖定 status 只有數量；有黑名單或本機狀態尚未核對時，先保留通知至解鎖分類，避免顯示封鎖者的活動。已解鎖、選擇顯示內容時，文字最多預覽 140 字元。通知中的時間與本文都不會交給 AI、專案、記憶或診斷。

## 驗證

- 兩帳號本機 TLS fixture 透過產品的 WinHTTP、裝置標頭、訊息 API、WIC 與加密檔案路徑執行。覆蓋重送同 UUID、模擬寫入故障時伺服器仍保留訊息、寫入後才 ack、回條、收件端刪除後寄件端仍保有紀錄、圖片、三種拒絕、14 天過期紀錄及封鎖者丟棄並 ack。
- Rust 測試覆蓋上鎖只輪詢 status、Unicode 長度、圖片尺寸／格式上限、EXIF 移除、日曆期間、索引重開、刪除金鑰後即使放回原密文也不能讀取，以及去重。加測 5,000 像素寬的 BMP 經 WIC 轉為 4,096 像素寬的 JPEG。
- Edge 以介面 fixture 驗證純文字、好友狀態、檔案選擇命令、Ctrl+V 圖片路由、送達與過期狀態、確認後清理、通知設定及鎖定清除。瀏覽器操作及原生 WIC 分開驗證。公司帳號、實體剪貼簿與可用私聊的原生視窗待公司環境驗收。
- MSVC v142 空快取 frozen、Clippy、無預設 features 與完整單執行緒 workspace 驗證通過，602 項 Rust 測試。三組獨立 TLS fixture 與七組 Edge 測試通過。一次 Edge 初始化提前結束，獨立重跑後通過。
- 原生 WebView2 自檢的分支、專案 composer、交接、截圖、任務追蹤及工作區六份收據通過。

依使用者指示，本版交付原始碼。正式公鑰提供後再安排 Release 與公司端驗收。
